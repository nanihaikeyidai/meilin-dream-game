# 前端交互优化方案 — UI/UX 升级 v0.4

> 分析人：明日香 | 日期：2026-05-14 | 面向：火舞（编码实现）
> 基于：frontend/game.html (773 行单页引擎，v0.3 状态)

---

## 一、现状总览

当前 game.html 实现了 AVG 引擎的核心闭环（开始→对话→选项→LLM 响应），但交互面粗糙，缺乏 AVG 应有的「沉浸感」和「控制感」。主要问题根因：所有精力花在了 AI 管线打通上，前端 UI 是功能验证态。

---

## 二、全量优化点清单（按优先级）

---

### P0 — 必须做（直接影响核心体验）

#### 1. 替换 prompt() 自定义输入

【问题】`openCustomInput()` 第 602 行调用浏览器原生 `prompt()` 弹窗。这个 API 在现代浏览器中被标记为不安全，Chrome 会弹"此页面试图弹出对话框"警告。UI 风格与游戏完全割裂。

【实现方案】
- 在 `choicesOverlay` 下方（或同级）添加一个自定义输入面板 `#customInputPanel`
- 面板包含：textarea 输入框 + 发送按钮 + 取消按钮
- 古风风格：半透明毛玻璃背景，毛笔字体，与游戏 UI 统一
- 调用方式：`openCustomInput()` 由 `prompt()` 改为显示该面板
- 快捷键：Ctrl+Enter 发送，Esc 取消

【预期代码位置】
- HTML：在 `choicesOverlay` 后新增 `<div id="customInputPanel">` 
- CSS：约 30 行，参考 choice-btn 的样式体系
- JS：修改 `openCustomInput()` 函数（约 10 行），新增事件监听

【验收标准】
- 点击"自由输入"按钮后显示内联输入面板，不是浏览器弹窗
- 输入框自动聚焦
- 发送后面板关闭，内容发送给 LLM
- 取消后回到选项界面
- 移动端输入体验正常

【为什么这么做】
prompt() 在移动端几乎不可用（iOS Safari 不支持），而且视觉上直接打破了 AVG 的沉浸感。这是最迫切的优化。

---

#### 2. 添加顶部菜单栏（退出 / 重新开始 / 存档读档入口）

【问题】游戏过程中没有任何菜单入口。玩家想退出只能刷新页面，想重开只能靠 F5，没有任何操作路径告知用户。

【实现方案】
- 在屏幕左上角添加一个隐藏式菜单按钮「☰」（三横线，半透明，hover 变亮）
- 点击弹出下拉菜单面板（毛玻璃效果），包含：
  - 保存进度（P1 功能，先留入口）
  - 加载进度（P1 功能，先留入口）
  - 重新开始（confirm 确认后 `location.reload()`）
  - 返回标题（回到开始画面，隐藏 gameScreen，显示 startOverlay）
  - 设置（P1 功能，先留入口）

【预期代码位置】
- HTML：在 `gameScreen` 内最顶层加 `<div id="menuBtn">` 和 `<div id="menuPanel">`
- CSS：约 40 行，z-index 15+，需要高于所有层
- JS：约 20 行，toggle 显示 + 各按钮事件

【验收标准】
- 菜单按钮始终可见（不遮挡剧情文本即可）
- 点击菜单按钮弹窗，点击外部关闭
- "返回标题"回到开始画面（不刷新页面，保留开始画面的状态）
- "重新开始"有确认弹窗（用自定义确认框，不要 confirm()）

【为什么这么做】
没有退出路径是基础可用性问题，用户会感到被困住。菜单是 AVG 的标准配置，也是后续功能（存档/设置）的入口容器。

---

#### 3. 选项入场动画 + 选项面板优化

【问题】选项是简单的 `display: none → flex`，没有过渡动画，出现突兀。选项面板固定在 `bottom: 100px`，在小屏手机上可能与文本框重叠。

【实现方案】
- 选项按钮入场：逐项 `@keyframes` 从底部滑入 + 透明度过渡，每个选项延迟 100ms
- 选项面板位置改为 `position: fixed; bottom: auto; top: calc(50% + 40px);` 居中偏下
- 背景遮罩：选项显示时加一层半透明遮罩 `position: fixed; inset: 0; z-index: 9`
- 选项面板本身的入场动画：从底部上滑 + 缩放

【预期代码位置】
- CSS：新增 `@keyframes choiceSlideIn`，修改 `.choices-overlay` 样式
- JS：在 `showChoices()` 中为每个按钮动态添加动画延迟（`style.animationDelay = i*100 + 'ms'`）

【验收标准】
- 选项出现时有"从底向上逐个滑入"的动效
- 背景变暗，聚焦选项
- 动画流畅，60fps
- 选项消失时也有退场动画

【为什么这么做】
选项是玩家做决策的时刻，是 AVG 中最有仪式感的交互节点。平滑的入场动画让玩家感受到"到你了"的明确信号，提升决策沉浸感。

### P1 — 重要（显著提升体验）

#### 4. 开始画面装饰升级

【问题】开始画面只有文字 + 渐变背景，没有装饰性元素。标题页在 AVG 中是品牌门面。

【实现方案】（按优先级排列，可按 sprint 分批做）
- 4a 背景装饰：在纯色渐变背景上叠加古风 SVG 装饰元素（灯笼、飘落花瓣/萤火虫粒子、远山剪影），用绝对定位 + CSS animation/transform
- 4b 标题动画：标题文字使用打字机效果或渐入效果（已有 fadeInUp 但不够精致）
- 4c 背景音：淡入播放一段古风背景音乐（留空位，先占位）

【预期代码位置】
- HTML：在 `startOverlay .inner` 的前后或同级加装饰 div
- CSS：约 60 行，使用 `@keyframes` + 伪元素
- 装饰元素可以用 CSS 绘制（伪元素），不需要额外图片

【验收标准】
- 开始画面不再"素面朝天"，至少有 2 种装饰元素
- 动画性能良好（使用 transform/opacity，不触发重排）
- 移动端适应

【为什么这么做】
开始画面是玩家对游戏的第一印象。目前的设计传达不出"古风长安"的氛围感，玩家在点击"开始故事"之前没有任何情感铺垫。

---

#### 5. 立绘入场动画 + 多位置支持

【问题】立绘通过 `opacity: 0 → 1` 切换。switch 时新旧立绘没有过渡，直接替换。立绘始终居中，不支持"左侧说话/右侧倾听"的经典 AVG 布局。

【实现方案】
- 5a 入场动画：新增从左侧/右侧滑入的动画（`@keyframes slideInLeft` / `slideInRight`），配上透明度过渡
- 5b 退场动画：旧立绘向左或向右滑出
- 5c 保留当前立绘在切换时的"浮现"效果（同一角色换表情时用交叉淡入淡出）
- 5d 多位置支持（可选）：增加 `char-layer-left` / `char-layer-right` 类，根据角色切换左右位置（需要 LLM 输出 [POS: left] 标签，或通过角色属性推断）
- 5e 多立绘支持（进阶）：两个 `.character-layer` 实例，实现双人对话

【预期代码位置】
- CSS：新增 `@keyframes slideInLeft`, `slideInRight`, `fadeOutLeft`
- JS：修改 `updateSprite()` 函数，添加动画类名控制

【验收标准】
- 立绘切换时有流畅的滑入/滑出动画
- 同一角色换表情时交叉淡入（不用滑入）
- 动画不卡顿

【为什么这么做】
立绘是 AVG 情感表达的核心载体。生硬的切换让角色"瞬移"，破坏叙事连续性。流畅的入场让每次角色出场都有"登台"的感觉。

---

#### 6. 文字逐字打印效果 + 速度控制

【问题】文本一次性渲染，没有逐字出现的"打字机"效果。这是 AVG 最标志性的文字呈现方式。

【实现方案】
- 在 `showPage()` 中，文本内容通过 `setInterval` 逐字（或逐词）插入到 textBody
- 默认速度：每字 30-50ms（可配置）
- 玩家点击屏幕时立即显示全文（skip to end）
- 添加"文字速度"配置（在设置面板中，可在 P2 实现）
- 对过短的文本（少于 20 字）直接显示，不逐字

【预期代码位置】
- JS：新增 `typeText(text, element, callback)` 函数，约 40 行
- 修改 `showPage()`：渲染文本改为调用 `typeText()`
- 修改 `advancePage()`：如果在打字中，则直接完成当前文本

【验收标准】
- 文本逐字出现，有节奏感
- 点击任意位置立即显示全部文本
- 翻页仅在完整显示后触发
- 不影响已有的事件处理逻辑

【为什么这么做】
逐字显示控制了阅读节奏，让玩家不会"一目十行"跳过氛围描写。这是 AVG 区别于普通阅读器的核心体验之一。也给了"点击完成打字"这个微交互机会，增加操作感。

---

#### 7. 全局键盘快捷键

【问题】目前只支持 Enter/Space/ArrowDown/ArrowRight 翻页。缺少 AVG 标配快捷键。

【实现方案】增强 keydown 事件处理：

| 按键 | 功能 | 状态 |
|------|------|------|
| Enter/Space | 翻页 / 确认选项 | 已有 |
| 方向键 ↑↓ | 选项导航（上下选择） | 新增 |
| Esc | 打开/关闭菜单 | 新增 |
| A | 自动播放（Auto 模式） | 新增 |
| S | 打开存档 | 新增 |
| L | 打开读档 | 新增 |
| H | 查看历史记录（log） | 新增 |
| Ctrl+Z / Cmd+Z | 回退到上一页（如果已翻页） | 新增 |

【预期代码位置】
- JS：扩展 `keydown` 监听器，约 30 行
- 新增 `handleChoiceNavigation(direction)` 函数处理选项键盘导航

【验收标准】
- 所有快捷键在对应状态下可用
- 快捷键有视觉反馈（如果有焦点提示）
- 不影响已有功能

【为什么这么做】
AVG 是重度键盘操作的类型。对喜欢"双手不离开键盘"的玩家来说，键鼠混合体验很差。快捷键是专业 AVG 引擎的标配。

### P2 — 锦上添花（迭代优化）

#### 8. 存档/读档系统（localStorage）

【问题】完全没有存档能力。玩家关闭页面后所有进度丢失。

【实现方案】
- 存档格式 JSON：`{ saveName, timestamp, messages (切片前 50 条), currentCharName, currentCharId, currentExpression, currentBackground, turnCount }`
- 存档槽：5 个插槽，显示时间戳 + 进度摘要（当前场景名）
- 读档：还原 messages + UI 状态
- 自动存档：每次 LLM 回复完成后自动存到 slot 0

【预期代码位置】
- JS：新增 `saveGame(slot)`, `loadGame(slot)`, `listSaves()` 函数，约 60 行
- HTML：存档/读档面板复用菜单面板的弹出逻辑

【验收标准】
- 存档时记录关键状态
- 读档后能继续游戏（LLM 上下文一致）
- 存档信息在页面刷新后仍然存在

【为什么这么做】
存档是 AVG 的基本人权。没有存档意味着玩家不敢关闭页面，这是不可接受的。

---

#### 9. 历史记录（Log）面板

【问题】无法回看已读过的文本。玩家翻页过快错过了内容就彻底丢失。

【实现方案】
- 每次 `showPage()` 时将当前页内容 + 角色名追加到 history 数组
- 历史面板以列表形式展示：左角色名 + 右对话文本
- 按时间倒序排列，最新在最下方
- 面板可以滚动，高度约为屏幕 70%

【预期代码位置】
- JS：新增 `historyLog[]` + `showHistory()` + `hideHistory()`，约 30 行
- HTML/CSS：新增 `<div id="historyPanel">`，约 40 行样式

【验收标准】
- 按 H 键弹出历史面板
- 显示所有已读文本
- 再次按 H 或点击外部关闭

【为什么这么做】
AVG 玩家习惯通过滚轮回看文本。没有历史日志违反了品类预期。

---

#### 10. Auto / Skip 模式

【问题】玩家必须手动点击每一页，没有自动播放或快进选项。

【实现方案】
- Auto 模式：每页显示完成后，等待 2-3 秒自动翻页
- Skip 模式：跳过所有文本，快速遍历到下一个选项（仅对已读文本有效；本游戏是 AI 生成剧情，可用"快速自动"代替）
- 在文本框右下角加图标指示 Auto/Skip 状态

【预期代码位置】
- JS：新增 `autoMode` 状态变量 + `autoAdvance()` 定时器逻辑，约 30 行
- 修改 keydown 监听：A 键切换 Auto，Ctrl 键按住时加速

【验收标准】
- Auto 模式下每隔约 2.5s 自动翻页
- 遇到选项时 Auto 暂停
- 可以随时手动点击打断 Auto

【为什么这么做】
Auto 模式是 AVG 玩家的"观影模式"。长篇叙事时一直手动点击很疲劳。

---

#### 11. 文本框 UI 细节优化

【问题】文本框样式功能完整但缺少细节打磨。

【优化项】
- 11a 角色名标签的装饰：左侧加一条竖线或小圆点（与角色主题色绑定，未来扩展）
- 11b 文本框点击区域优化：目前整个文本窗口是 `pointer-events: auto`，建议区分"点击翻页"和"点击不操作"区域
- 11c 翻页指示器动画：▼ 图标有脉冲动画（已有），但建议改成"更多翻页提示"或"自动模式"动态指示
- 11d 文本边距在小屏适配：当前 `padding: 18px 28px 28px` 在 375px 宽度下左右空间紧张

【验收标准】
- 角色名区域视觉更突出
- 翻页指示器在无更多页时更明显
- 小屏适配无溢出

## 三、改动风险评估

| 优化项 | 风险等级 | 说明 |
|--------|----------|------|
| 替换 prompt() | 低 | 纯新增 UI 组件，不触及核心逻辑 |
| 菜单栏 | 低 | 纯新增，不干涉现有 z-index 层级 |
| 选项动画 | 低 | CSS 改动为主，不影响 JS 逻辑 |
| 开始画面装饰 | 低 | 新增元素，不改变交互逻辑流 |
| 立绘动画 | 中 | 涉及 updateSprite 逻辑修改，需注意时序 |
| 逐字打印 | 中 | 改变文本渲染流程，需要处理"打字中点击"事件 |
| 键盘快捷键 | 低 | 纯新增，注意不要与已有快捷键冲突 |
| 存档/读档 | 中 | 状态序列化需要覆盖所有 GameState 字段 |
| 历史记录 | 低 | 纯新增面板 + 数据收集 |
| Auto/Skip | 低 | 纯新增状态管理 |

## 四、实施建议优先级

### 第一轮 sprint（2-3 小时工作量）

1. 替换 prompt() → 自定义输入面板（P0，约 40 行代码）
2. 添加顶部菜单 + 退出/重开入口（P0，约 60 行代码）
3. 选项入场动画（P0，约 30 行 CSS + 5 行 JS）

这三项可以并行做，互不依赖。完成后游戏具备基本可用性。

### 第二轮 sprint（3-4 小时工作量）

4. 开始画面装饰（P1，纯 CSS）
5. 立绘入场动画（P1，CSS + 少量 JS）
6. 逐字打印效果（P1，纯 JS 改动）

立绘动画和逐字打印有少量交互影响（逐字打完前立绘不应消失），需要串行验证。

### 第三轮 sprint（2-3 小时工作量）

7. 键盘快捷键扩展（P1）
8. 存档/读档（P2）
9. 历史记录（P2）
10. Auto 模式（P2）

存档和读档与菜单入口配合，建议一起做。
