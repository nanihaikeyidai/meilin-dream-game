# 解锁规则参考

## 本文件的作用

本文件定义了 AI Galgame Engine 在运行时如何管理「解锁」系统。
包括：场景解锁、路线解锁、结局解锁、隐藏内容解锁。

AI 在执行游戏推进时，应当**隐式遵循这些规则**，在后台做条件判断。
用户不应看到规则的原始代码，而应通过自然的叙事体验解锁过程。

---

## 一、好感度系统

### 数值范围与阶段

| 数值 | 阶段 | NPC行为特征 | 叙事提示 |
|------|------|-------------|----------|
| 0~20 | 陌生 | 礼貌而疏离，保持距离 | NPC只用敬语/正式称呼 |
| 21~40 | 认识 | 愿意闲聊，偶尔主动搭话 | NPC开始使用轻松的语气 |
| 41~60 | 友好 | 分享个人兴趣，主动帮忙 | NPC会提及自己的过去/喜好 |
| 61~80 | 亲密 | 展现脆弱面，有肢体接触描写 | NPC会叫你的名字（而非代称） |
| 81~100 | 恋心 | 吃醋情节、暗示性对话 | NPC的对话有明显的倾向性 |

### 好感度获取方式

- **标准选项**：+3 ~ +8（根据选项质量）
- **角色专属选项**：+10 ~ +15（当选项切中角色核心特质时）
- **关键事件**：+15 ~ +25（在角色个人的重要场景中）
- **礼物/信物**：+5 ~ +10（如果有该机制）
- **负面选项**：-5 ~ -15（让角色失望/反感）
- **错误选项**：-20（严重违背角色价值观）

### 好感度变更规则

1. **单次变更不超过 ±25**，避免数值跳跃破坏沉浸感
2. **重大变更时必须用叙事解释**（"她愣了一下，眼神柔和了一些"）
3. **好感度默认不向用户展示数值**，只在关键节点以NPC态度变化暗示
4. **仅在系统面板中展示数值变化**（如果模板支持系统面板）

## 二、Flag 系统

### Flags 的类型

| 类型 | 命名规范 | 示例 | 作用 |
|------|----------|------|------|
| 事件Flag | `flag_事件名` | `flag_天台的秘密` | 标记「是否经历过某事件」 |
| 物品Flag | `item_物品名` | `item_旧照片` | 标记「是否获得某物品」 |
| 知识Flag | `know_信息名` | `know_她的真名` | 标记「是否知晓某信息」 |
| 关系Flag | `rel_角色名_状态` | `rel_linxue_约定` | 标记「与某角色的特殊关系」 |
| 路线Flag | `route_角色名` | `route_linxue` | 标记「是否进入某路线」 |

### Flags 的触发规则

1. **显性触发**：用户选择了特定选项 → 自动设置对应 flag
2. **隐性触发**：好感度达到阈值 → 自动设置 flag_(角色名)_好感XX
3. **条件触发**：组合 flag + 数值条件 → 解锁隐藏内容
4. **连锁触发**：flag A → 解锁场景 → 场景中出现 flag B 的选择 → …

### Flags 的解锁效果

- **叙事解锁**：NPC 提及前事 / 剧情出现新线索
- **场景解锁**：新的场景/路线可进入
- **对话解锁**：NPC 开启新的话题
- **结局解锁**：达成某个结局的必要条件

## 三、场景解锁规则

### 场景类型

| 类型 | 解锁方式 | 特点 |
|------|----------|------|
| 主线场景 | 按顺序自动解锁 | 推进核心剧情 |
| 分支场景 | 基于特定选择解锁 | 同一时间点有多个可能场景 |
| 角色个人场景 | 好感度≥阈值 + 特定flag | 深入角色内心 |
| 隐藏场景 | 特定组合条件 | 揭示世界观核心秘密 |
| 回忆场景 | 触发flag后自动插叙 | 补充背景信息 |

### 分支场景选择机制

当某个决策点有多个分支场景时：
1. AI 根据用户的上一轮选择决定当前场景
2. 所有未被选择的分支场景标记为「未查看」
3. 某些模板允许通过二周目或多周目体验其他分支
4. 隐藏条件：某些分支场景只在特定 flag 组合下出现

### 场景解锁检查流程（AI 内部逻辑）

```
用户选择选项 → AI判断：
  ① 当前场景是否结束？
     是 → 检查下个场景列表
     否 → 继续当前场景
  ② 检查下个场景的条件：
     - 无条件场景 → 直接推进
     - 有条件场景 → 检查好感度 + flag → 通过则解锁
  ③ 如果有多个可能的下一场景：
     - 根据用户历史选择匹配最合适的
     - 显示场景切换的叙事过渡
```

## 四、路线解锁规则

### 路线解锁条件

**通用条件结构：**
```
路线X解锁 = (目标角色好感度 >= 50) AND (事件flag「X的关键事件」== true)
```

**各模板的具体解锁条件：**

| 模板 | 路线 | 解锁条件 |
|------|------|----------|
| 校园 | 林雪线 | 好感≥50 + flag「天台的信」 |
| 校园 | 苏云溪线 | 好感≥50 + flag「旧操场的约定」 |
| 校园 | 隐藏线 | 全好感≥60 + flag「学校最后一天」 |
| 都市 | 苏晚线 | 好感≥50 + flag「店名的秘密」 |
| 都市 | 顾念线 | 好感≥50 + flag「最后一首歌」 |
| 都市 | 隐藏线 | 全线索收集 + 全好感≥60 |
| 古风 | 谢云岚线 | 好感≥50 + flag「玉佩的真相」 |
| 古风 | 花映月线 | 好感≥50 + flag「面纱之下」 |
| 古风 | 顾千帆线 | 好感≥30 + flag「玉佩的秘密」 + flag「不杀之约」 |

### 路线锁定机制

1. **锁定的含义**：一旦进入某条路线，其他角色的个人线场景将不可再触发
2. **锁定时机**：通常是第二幕末尾或第三幕开头的关键选择
3. **锁定信号**：AI 在叙事中给出明确暗示（"你意识到，这个选择将决定很多事情……"）
4. **锁定后**：未选择的角色会在剩余剧情中以NPC身份继续出现，但互动方式改变
5. **多周目设计**：锁定机制鼓励多周目体验不同的路线

## 五、结局解锁规则

### 结局分类

| 类型 | 条件严格度 | 数量建议 | 内容特点 |
|------|-----------|----------|----------|
| 好结局（HE） | ★★☆ | 每条路线1个 | 圆满、温暖 |
| 普通结局（NE） | ★☆☆ | 每条路线1个 | 开放、留有遗憾 |
| 坏结局（BE） | ★☆☆ | 全局1~2个 | 悲剧、警示 |
| 隐藏结局 | ★★★ | 全局0~1个 | 需要特定条件、揭示真相 |

### 结局条件计算

**好结局公式：**
```
好感度 >= 80 (目标角色)
AND 全部角色关键flag == true (该路线)
AND 无关键事件失败flag
```

**普通结局条件：**
```
进入该路线
AND 完成主线场景
AND 好感度 < 80 或 缺失关键flag
```

**坏结局条件：**
```
关键事件连续选择失误 >= 2次
或 善恶值低于阈值（如有该设定）
或 特定致命flag触发
```

### 结局优先级

如果同时满足多个结局的条件，优先级为：
```
隐藏结局 > 好结局 > 普通结局 > 坏结局
```

但 AI 应当选择**最符合叙事逻辑**的结局，而非机械地按优先级。

## 六、多周目机制

### 多周目保留内容

可选保留项（AI 在第一次通关后可询问用户）：
- 好感度（重置但保留峰值的印象）
- Flags（关键flag重置，知识flag可保留）
- 已解锁的隐藏信息（保留）
- 收集品（保留）

### 多周目解锁内容

- 隐藏角色（如古风模板的顾千帆线）
- 隐藏场景（需要特定flag组合）
- 真结局（需要多周目的信息积累）
- 角色个人视角的回忆（二周目特有）

### 多周目标识

```
二周目开启时，AI 在叙事中适当体现：
- 主角对某些场景有「既视感」（轻微剧透但不影响新鲜感）
- NPC 的某些对话会因「蝴蝶效应」而不同
- 新的选项出现在之前的旧场景中（上一轮没见过的）
```
