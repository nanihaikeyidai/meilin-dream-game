# 角色系统参考

## 本文件的作用

AI 在生成和扮演 NPC 时，应当遵循本文件定义的规范，以确保角色的一致性和深度。

---

## 一、角色设定清单

每个 NPC 应包含以下完整信息（AI 在生成角色时自动填充）：

### 基础信息
```markdown
## [角色名]

**基本信息**
- 姓名：
- 年龄：
- 性别：
- 身份/职业：
- 与主角的关系：

**外貌描写**
- 发型/发色：
- 着装风格：
- 标志性特征：（疤痕、配饰、习惯动作等）
- 第一印象：（路人视角的描述）

**性格档案**
- 核心特质：（3个关键词）
- 性格类型：（如 MBTI 或类似分类）
- 优点：
- 缺点：
- 矛盾之处：（外在表现与内心的反差）
- 压力下的反应：

**背景故事**
- 过去经历：
- 关键事件：
- 未解心结：
- 深藏的秘密：（由剧情逐渐揭示）
```

### 对话风格设定
```markdown
**说话方式**
- 语速：（快/中等/慢，可加形容词如「慵懒地」「急促地」）
- 语气词：（「嗯…」「那个…」「喂！」）
- 口癖/习惯用语：
- 称呼别人的方式：（全名/昵称/职务）
- 生气时的表现：
- 开心时的表现：
- 紧张时的表现：
```

## 二、角色关系网

### 关系类型

| 关系 | 特征 | 对话风格 |
|------|------|----------|
| 陌生人 | 礼貌、保持距离 | 敬语、短句 |
| 朋友 | 轻松、可开玩笑 | 语气随意、有互动感 |
| 好友 | 分享秘密、互相吐槽 | 使用昵称、有私密话题 |
| 暧昧 | 试探、暗示、关心 | 双关语、停顿、未尽之言 |
| 恋人 | 亲密、独占欲 | 直白表达、肢体接触描写 |

### 角色之间关系

AI 在推进剧情时，不仅追踪 NPC 与主角的关系，还应追踪 NPC 之间的隐性关系网：

```json
{
  "character_relationships": [
    { "from": "苏晚", "to": "周医生", "type": "旧识", "affection": 60, "detail": "大学同学，有一段未说清的往事" },
    { "from": "顾念", "to": "苏晚", "type": "常客朋友", "affection": 40, "detail": "顾念是店里最早的老顾客" },
    { "from": "谢云岚", "to": "花映月", "type": "对立", "affection": -30, "detail": "玄天司正在追查月影阁" }
  ]
}
```

NPC 之间的关系会间接影响 NPC 对你的态度。

## 三、角色成长弧

每个可攻略角色应有一条完整的「成长弧」，即角色在故事中获得的变化：

### 标准四段式成长弧

```
第一阶段：出场印象（固化形象）
  ↓ 通过与主角的互动
第二阶段：出现裂痕（展现反差）
  ↓ 通过关键事件
第三阶段：本质展露（揭示真相）
  ↓ 通过最终选择
第四阶段：成长/坠落（结局状态）
```

### 示例（林雪）

```
阶段一：温柔安静的班长，成绩好但社交少
阶段二：发现她其实很在意别人的看法，害怕被遗忘
阶段三：毕业那天她本打算告白但放弃了，把信藏在了天台
阶段四（HE）：学会勇敢表达，不再隐藏自己
阶段四（NE）：继续隐藏自己，错过之后留下遗憾
```

AI 应当根据用户的选择，自然地**展现角色的变化**，而不是在某个节点突然宣布「她变了」。

## 四、角色专属事件

### 事件触发层级

```
主线事件 ← 所有玩家都会经历
  └── 角色个人事件 ← 好感度/路线限定
        └── 隐藏事件 ← 特定flag组合
              └── 结局事件 ← 以上全部条件
```

### 角色个人事件类型

| 事件类型 | 触发时机 | 内容特点 | 好感度影响 |
|----------|----------|----------|------------|
| 日常事件 | 好感 20+ | 一起做日常小事 | +3~5 |
| 兴趣事件 | 好感 35+ | 带你去ta喜欢的地方 | +5~8 |
| 过去事件 | 好感 50+ | 提到过去的经历 | +8~12 |
| 脆弱事件 | 好感 65+ | 展现弱点或求助 | +10~15 |
| 核心事件 | 路线解锁 | 角色弧光的转折点 | +15~25 |
| 告白事件 | 好感 85+ | 感情的关键表达 | 取决于回应 |

## 五、多角色平衡

当模板有多个可攻略角色时，AI 应当：

1. **公平出场**：每个角色在前期有大致均等的出场机会
2. **自然退场**：当用户明显偏向某角色时，其他角色逐渐退为配角，而非突然消失
3. **间接影响**：选择A会影响B的态度（「听说你昨天和A去了天台？」）
4. **不可兼得**：某些角色之间有冲突，无法同时高好感

## 六、NPC之间的互动动力学

### 6.1 NPC关系的类型

每个 NPC 与其他 NPC 之间的关系都应明确归类，放在角色卡的「与其他角色的互动」中。关系类型包括：

| 关系类型 | 特征 | 叙事表现 |
|----------|------|----------|
| 旧识 | 曾经认识，有一定了解 | 见面时会提起过去的事 |
| 好友 | 互相欣赏，有共同话题 | 会互相调侃、帮忙、掩护 |
| 对立 | 立场不同，可能有冲突 | 见面时气氛紧张，言语带刺 |
| 单箭头 | 一方对另一方有未说出口的感情 | 注视、回避、反常的沉默 |
| 亏欠 | 一方欠另一方什么 | 回避目光，或过度补偿 |
| 陌生 | 几乎不认识 | 互相客气，但无话可说 |
| 恩怨 | 有复杂的过去 | 欲言又止，说不清是敌是友 |

### 6.2 NPC互动场景类型

AI 在推进剧情时，应主动生成以下类型的 NPC 互动场景：

#### 类型一：双人对话（主角在场）

NPC A 和 NPC B 在你面前说话。你不一定需要插话——你可以选择听。

> **示例（都市模板）：**
> 顾念推门进来，看到秦雨桐坐在窗边，愣了一下。
> 「……你来了。」
> 「嗯。」秦雨桐没抬头。「今天的节目临时取消了。」
> 顾念把吉他放在吧台边，沉默了一会儿。「那首曲子——我改了个版本。」
> 秦雨桐的手指停在杯子边缘。「……我不想听。」
> 但她的眼睛出卖了她。

**选择可能：**
```
1.【留下来听她们说】（观察）
2.【找个借口走开，把空间留给她们】（体贴）
3.【「什么曲子？我能听听吗？」】（介入）
0.【自由行动】
```

#### 类型二：三人以上群戏

三个以上的 NPC 同时在场时，描写他们之间的空间关系和微表情。

> **示例（古风模板）：**
> 谢云岚站在左侧，手按在剑柄上，目光冷峻。
> 花映月坐在屏风前的软塌上，团扇半遮面，眼神在谢云岚和你之间来回。
> 顾千帆隐在角落的阴影里——他没拔剑，但他的手已经握住了剑柄。
> 房间里四个人，三种立场。
> 没有人先开口。

**群戏描写要点：**
- 谁和谁站在/坐在一起（物理距离 = 心理距离）
- 谁在回避谁的目光（有愧/有秘密）
- 谁先开口，谁保持沉默（立场和性格的体现）
- 谁在观察谁（掌握信息更多的一方通常更沉默）
- 空气突然安静的时刻（某句话触到了雷区）

#### 类型三：侧写事件（主角不在场）

有一些 NPC 之间的故事是主角没有亲眼看到的，但可以通过以下方式了解：

- **事后对话**：「昨天她来店里找你了——你没在，她坐了一会儿就走了。」
- **留下的痕迹**：一张字条、一杯没喝就走的咖啡、被翻过的书页
- **第三方的转述**：「你听说了吗？昨晚她们大吵了一架。」
- **日记/信件/录音**：NPC 的记录中提到了与其他 NPC 的互动

> **示例：**
> 你第二天到店里的时候，苏晚正在吧台后面发呆。
> 你注意到——吧台上放着一杯没动过的黑咖啡。
> 「……赵逐昨晚来过了。」
> 她没多说什么。但那杯咖啡一直放到打烊，她没倒掉。

**侧写事件的作用：**
- 让 NPC 之间的关系显得更真实（他们有自己的故事，不只活在主角在场时）
- 制造悬念和伏笔
- 让世界观更有沉浸感

#### 类型四：关系变化——NPC之间的关系随着剧情推进

NPC 之间的关系不是静态的。它会随着以下因素变化：

| 影响因素 | 变化示例 |
|----------|----------|
| 主角选择了 A 的路线 | B 和 C 因为共同的失落而走得更近 |
| 主角促成了和解 | 原本有矛盾的 NPC 关系缓和 |
| 主角无意中造成了误会 | 两个 NPC 因为主角的某个行为而产生隔阂 |
| 时间推移 | 原本对立的关系因共同目标而合作 |

AI 应当在每次关键节点后更新 NPC 关系状态，并在后续叙事中体现变化。

> **示例（关系变化）：**
> 第一次见面：「谢云岚和花映月见面时互相点头——客气但疏离。」
> 经历事件后：「谢云岚在追捕中放了花映月一马。她回头看了他一眼，什么也没说。」
> 终局：「长安城楼上，谢云岚和花映月并肩站着。一个前朝遗孤站在他们身后。三个本不该站在一起的人，今天站在了同一边。」

### 6.3 NPC互动在记忆中的记录

每个角色的「与其他角色的互动」部分应包含：

```json
{
  "relationships": {
    "NPC_A": { "type": "旧识", "affection": 60, "status": "current", "key_events": ["三年前的某件事", "最近的和解"] },
    "NPC_B": { "type": "对立", "affection": -20, "status": "紧张", "key_events": ["在主角面前争吵"] }
  }
}
```

AI 应当在 `session.json` 中追踪这些关系的变化。

### 6.4 NPC互动选择选项设计

当 NPC 之间正在互动时，选项应当包括：

1. **观察/倾听** —— 不打断，看事态发展（增加信息量）
2. **介入/说话** —— 主动参与NPC之间的对话（影响关系走向）
3. **离开/回避** —— 把空间留给他们（体贴但减少信息量）
4. **自由行动**

每种选择都会影响 NPC 之间的关系和 NPC 对你的看法。

## 七、用户自定义角色处理

当用户自定义主角时，AI 应当：

1. **尊重设定**：完全采用用户提供的人设
2. **主动呼应**：在叙事中提到用户设定（如「你习惯性地用左手撑着下巴」）
3. **调整NPC反应**：不同的主角性格会影响NPC的初始态度
   - 活泼型主角 → 容易获得开朗NPC好感，但可能让文静NPC觉得吵
   - 沉默型主角 → 容易获得文静NPC信任，但可能让开朗NPC觉得闷
4. **保持一致性**：不要在后续剧情中违背用户设定的人设

## 八、对话生成规范

### 好的对话 vs 不好的对话

**不好的对话：**
```
「你好。」（无个性）
「今天天气真好。」（无信息量）
「我很开心。」（平铺直叙）
```

**好的对话：**
```
「唔…这个点了还有人进来啊。」她抬眼看了你一下，又低下头擦杯子。
「你猜。」她歪了歪头，眼里带着一丝狡黠的光。
「……没什么。只是想到了一些以前的事。」她顿了一下，目光落在窗外。
```

### 对话中的「潜台词」

AI 应在对话中加入未言明的信息，让对话有层次感：

```
表面台词：「你还没走啊。」（关心中带着一丝意外）
潜台词：「我其实一直在注意你有没有离开。」
```

### 反应随好感变化

同一句话，在不同的好感阶段应有不同的反应方式：

```
好感 10：「嗯。」（低头看书，简短回应）
好感 30：「嗯？你说什么？」（抬起头，愿意再听一遍）
好感 50：「嗯…你刚才说的那个，我觉得挺有意思的。」（主动延续话题）
好感 70：「嗯。其实我也想跟你说件事…」（开始分享自己的事）
```
