# Galgame 记忆系统架构

## 问题

AI 的上下文窗口有限（Claude Code 约 200K tokens）。
当游戏进行到第 3 幕时，第 1 幕的对话、选择、flag 会被推出上下文。
结果：AI 忘记之前发生过什么，角色行为不一致，好感度失去意义。

## 解决方案：三级记忆架构

```
┌─────────────────────────────────────────┐
│           ① 工作记忆（上下文内）          │  ← 每轮对话都在
│   Game State Card — 紧凑的状态摘要        │
│   包含：当前场景 / 好感度 / flags / 近况   │
└─────────────────────────────────────────┘
                    ↕ 每次选择后更新
┌─────────────────────────────────────────┐
│        ② 会话记忆（JSON 缓存文件）        │  ← 每回合自动更新
│   .galgame/session_[slot].json           │
│   包含：完整状态 / 最近5条历史 / 摘要     │
└─────────────────────────────────────────┘
                    ↕ 关键节点自动保存
┌─────────────────────────────────────────┐
│          ③ 存档文件（JSON 持久化）        │  ← 用户可读档/存档
│   .galgame/save_[slot].json              │
│   包含：全部游戏状态 / 历史记录           │
└─────────────────────────────────────────┘
```

---

## ① 工作记忆（Game State Card）

**格式**：紧凑、人眼可读、单行或几行。

AI **必须**在每次响应的末尾（系统面板之前）附带这个 State Card。

```
[GALGAME STATE]
Scene: act2_rooftop | Route: linxue | Act: 2/3
❤ Linxue: 62  |  Yunxi: 28
🏁 met_linxue ✓ | rooftop_secret ✓ | old_photo ✓
Recent: ① "comfort her" ② "follow to rooftop" ③ "ask about box"
Progress: 12/25
```

### 自定义输入在 State Card 中的标识

当用户选择了自定义输入（自由行动）时，Recent 中用 ✎ 标记：

```
Recent: ① "comfort her" ② ✎ "我轻声叫了她的名字" ③ "follow to rooftop"
```

### 字段说明

| 字段 | 内容 | 示例 |
|------|------|------|
| Scene | 当前场景 ID | `act2_rooftop` |
| Route | 当前路线（nil 表示未锁定） | `linxue` / `nil` |
| Act | 当前幕 / 总幕数 | `2/3` |
| ❤ | 好感度（只显示>=10的角色） | `Linxue: 62` |
| 🏁 | 已触发的关键 flag | `met_linxue ✓` |
| Recent | 最近 3~5 个用户选择 | `"comfort her"` / `✎ "自定义内容"` |
| Progress | 已做决策数 / 总数 | `12/25` |

### 更新规则

- **每个用户选择后**：AI 重新计算并更新 State Card
- **放在响应的末尾**（选项之后，系统面板之前）
- **不在 State Card 中显示未解锁的信息**
- **自定义输入截断至 20 字**，过长则用「...」结尾

## ② 会话记忆（Session Cache）

**位置**：`.galgame/session_[slot].json`

**更新频率**：**每个交互回合**（每次用户选择一个选项或自由输入后自动写入）

**用途**：
- 防止意外中断丢失进度
- 多设备间携带进度（文件同步）
- AI 重新加载时可快速恢复上下文

**结构**：

```json
{
  "meta": {
    "game_version": "1.0",
    "template": "campus-summer",
    "last_updated": "2026-05-05T14:30:00Z",
    "total_decisions": 12
  },
  "protagonist": {
    "name": "陈远",
    "gender": "男",
    "personality": "沉默寡言但细心"
  },
  "state": {
    "current_route": "linxue",
    "current_act": 2,
    "current_scene": "act2_rooftop",
    "scene_progress": ["act1_classroom", "act1_hallway", "act1_courtyard", "act2_rooftop"],
    "unlocked_routes": ["linxue"]
  },
  "affection": {
    "linxue": 62,
    "yunxi": 28
  },
  "npc_relationships": {
    "linxue_yunxi": { "type": "好友", "affection": 45, "status": "稳定", "key_events": ["初中同学"] },
    "linxue_shenqingci": { "type": "不熟", "affection": 15, "status": "普通" },
    "yunxi_jiangxiaoyu": { "type": "好友", "affection": 50, "status": "活跃", "key_events": ["社团同部"] }
  },
  "flags": {
    "met_linxue": true,
    "rooftop_secret": true,
    "old_photo": true,
    "linxue_route_unlocked": true

    {"scene": "act1_courtyard", "choice_index": 1, "choice_text": "「树可以移走，回忆不会」", "type": "preset", "result": "linxue +15"},
    {"scene": "act1_courtyard", "choice_index": 0, "choice_text": "「我有个问题想问你很久了……」", "type": "custom", "result": "linxue +12, flag: deep_talk"},
    {"scene": "act2_rooftop", "choice_index": 1, "choice_text": "「是日记吧？」", "type": "preset", "result": "linxue +10"}

    "在教室遇到了林雪",

    "林雪问毕业后还会不会见面"
  ]

```

### Recent History 格式

```json
{
  "scene": "场景ID",
  "act": 1,
  "choice_index": 0,
  "choice_text": "用户选择的选项文本，或自定义输入的内容",
  "type": "preset | custom",
  "effects": {
    "affection_changes": { "角色ID": 5, "角色ID2": -3 },
    "flags_set": ["flag名"],
    "route_change": null
  },
  "narration_summary": "一句话描述发生了什么"
}
```

- `type: "preset"` — 用户选了预设选项
- `type: "custom"` — 用户自由输入
- `choice_index`: 预设选项为编号（1/2/3），自定义选项为 `0`

限制：最多保留 10 条。超过时移除最早的。

### Events Summary 格式

字符串数组，每幕最多 3 条核心事件摘要：

```json
[
  "在教室遇到了林雪",
  "在老榕树下谈了未来的事",
  "在天台上发现了林雪藏的旧物盒"
]
```

限制：最多 15 条。超过时移除最早的，但保留每幕最后 1 条。

## ③ 持久化存档（Save Files）

**位置**：`.galgame/save_[0-8].json`

**创建时机**：仅在以下情况写入（不是每回合都写）：
- ✅ 章节/幕结束
- ✅ 路线锁定/切换
- ✅ 重要 flag 获得
- ✅ 好感度发生 ≥15 的重大变动
- ✅ 重大选择（影响后续结局的选择）
- ✅ 用户主动保存（对话中说「保存一下」）
- ✅ 游戏结束/抵达结局

**与 Session Cache 的区别**：

| 维度 | Session Cache | Save Files |
|------|---------------|------------|
| 更新频率 | 每回合 | 关键节点 |
| 文件数量 | 1 个 | 最多 9 个（多存档位） |
| 用途 | 崩溃恢复、热启动 | 用户主动读档、多周目 |
| 格式 | 完整状态 + 近期摘要 | 完整状态 + 完整历史 |

## 记忆文件操作流程

### 启动游戏（新建）

```
1. AI 检查 .galgame/ 目录是否存在
   不存在 → 创建目录
2. 用户创建角色
3. AI 初始化状态对象
4. AI 写入 session.json（初始状态）
5. 开始游戏
```

### 继续游戏（读档）

```
1. AI 扫描 .galgame/save_*.json 文件
2. 显示存档列表给用户
3. 用户选择存档
4. AI 读取对应的 save JSON → 重建完整状态
5. AI 读取最后 3 条 recent_history 恢复「手感」
6. 重新开始叙事
```

### 每回合更新

```
用户选择 → AI 处理：
  ① 更新 affection / flags / progress
  ② 生成新的叙事 + 选项 + State Card
  ③ 检查是否触发「自动保存条件」
     是 → 写入 session.json + 写入 save slot
     否 → 只写入 session.json
  ④ 返回响应（包含 State Card）
```

### 游戏中断恢复

```
用户说「我们继续上次的」→ AI：
  ① 检查 .galgame/session.json
  ② 读取状态
  ③ 用 recent_history 最后 3 条和 events_summary 重建上下文
  ④ 继续叙事
```

## Auto-Save 条件详细表

| 条件 | 触发动作 | 示例场景 |
|------|----------|----------|
| 章节/幕结束 | session + save | 完成 Act 1，进入 Act 2 |
| 路线锁定 | session + save | "你意识到，这个选择将决定很多事情…" |
| 好感度跨阶（±15+ 或跨越阈值） | session + save | 好感 48→63（跨越 50 阈值） |
| 获得关键 flag | session + save | flag「天台的秘密」 |
| 重大选择（标记为 ★） | session + save | 是否接受告白 |
| 普通选择 | session 仅更新 | 日常对话选项 |
| 游戏结束/结局 | session + save | 结局画面出现时 |
| 用户说「存档」 | session + save | 用户主动请求 |
| 重新开始/读档 | 读取 save | 用户选择存档 |


## 多项目隔离

每个游戏项目有自己独立的 `.galgame/` 目录。
不同模板/项目之间不共享存档。

## AI 行为规范（记忆相关）

### 必须做的事

1. **每轮响应末尾附带 State Card**（如上所述的格式）
2. **每个用户选择后更新 session.json**（写入磁盘）
3. **达到自动保存条件时，更新 save 文件**（同时更新 session）
4. **启动时检查 .galgame/ 目录**，如存在则询问是否继续

### 禁止做的事

1. **不要在 State Card 中显示用户本不应该知道的信息**
   （如未解锁角色的好感度、未触发的隐藏 flag）
2. **不要忘记更新** — 每个用户交互后都必须刷新内存
3. **不要在回复中展示原始 JSON** — 用户看到的是 State Card 格式
4. **不要在存档中保存不必要的历史** — 限制 recent_history 为最近 10 条

## ④ 感知隔离系统（Perspective Isolation）

### 问题

传统的记忆系统把所有信息存在一起。结果：
- 林雪的秘密 → AI 让苏云溪也知道了 → 人设崩塌
- 主角单独对林雪说的话 → AI 让江晓渔引用 → 逻辑崩溃
- NPC 之间的私人对话 → 其他 NPC 莫名其妙知道 → 沉浸感归零

### 解决方案：每人物独立视角

每个角色（主角 + 所有 NPC）拥有**自己的视角文件**，只记录他们：
- 亲眼目睹的事件
- 亲耳听闻的信息（含信息源）
- 亲口说过的话（含对谁说的）
- 内心的秘密（仅自己知道）

```
.galgame/saves/周目名/perspectives/
├── index.md              ← 视角文件索引清单
├── protagonist.md        ← 主角知道的一切
├── linxue.md             ← 林雪的视角
├── suyunxi.md            ← 苏云溪的视角
├── shenqingci.md         ← 沈清辞的视角
├── jiangxiaoyu.md        ← 江晓渔的视角
├── xiazhiyao.md          ← 夏知遥的视角
├── chengnian.md          ← 程念慈的视角
└── yexiaoman.md          ← 叶小满的视角
```

### 视角文件格式

```markdown
# 视角 · 林雪

## 【目睹的事件】
| 时间 | 事件 | 在场者 |
|------|------|--------|
| 序章·教室重逢 | 主角推门进来，我们重逢了 | 主角、本人 |
| 一章·图书馆 | 在图书馆遇到主角和江晓渔 | 主角、本人、江晓渔 |
| 二章·天台 | 和主角在天台单独聊天 | 主角、本人 |

## 【听闻的信息】
| 内容 | 信息来源 | 何时得知 |
|------|----------|----------|
| 主角喜欢村上春树 | 主角亲口告诉 | 一章·图书馆 |
| 下周末有校庆活动 | 江晓渔说的 | 一章·图书馆 |
| 苏云溪最近在学吉他 | 路过琴房听到 | 二章·走廊 |

## 【亲口说过的话】
| 说了什么 | 对谁说 | 何时 |
|----------|--------|------|
| 「我高中时…其实很羡慕你」 | 主角 | 序章·教室 |
| 「周末要不要一起去琴行？」 | 苏云溪 | 二章·走廊 |

## 【内心秘密（仅自己知道）】
- 其实从高一开始就悄悄注意主角了
- 觉得自己毕业后和所有人都会失去联系
- 没告诉任何人那个旧物盒里装的是什么
```

### 黄金规则（强制）

```
╔═══════════════════════════════════════════════════════════╗
║                                                           ║
║   NPC A 在对话中只能引用 NPC A 视角文件中的内容。          ║
║                                                           ║
║   如果某条信息只存在于 NPC B 的视角文件中，               ║
║   NPC A 不能知道它、不能提到它、不能暗示它。              ║
║                                                           ║
║   主角可以选择「告诉」NPC A 某件事 →                     ║
║   该信息才会写入 NPC A 的视角文件。                       ║
║                                                           ║
╚═══════════════════════════════════════════════════════════╝
```

### 信息传播规则

信息在不同角色之间传播的**唯一途径**：

| 传播路径 | 方式 | 示例 |
|----------|------|------|
| 主角 → NPC | 主角亲口告诉 NPC | 主角告诉林雪自己害怕打雷 → 写入林雪的「听闻」 |
| NPC → 主角 | NPC 对主角说话 | 林雪向主角坦白心事 → 写入主角的「听闻」 |
| NPC A → NPC B | NPC A 当着 NPC B 的面说话 | 苏云溪在林雪面前说漏嘴 → 写入林雪的「听闻」 |
| 主角不在场时 | NPC 之间的私下对话 | 林雪和苏云溪私下聊天 → 写入双方「亲口说/听闻」 |
| 所有人在场 | 公开事件所有人都看到 | 大家一起目睹某事 → 写入所有人的「目睹」 |

**信息不会自动传播。** 即使 A 和 B 同时在场，A 心中所想也不会自动进入 B 的视角文件——除非 A 说出来了、或者 B 观察到了。

### 侧写事件的处理

当发生「主角不在场的 NPC 互动事件（侧写事件）」时：

1. 先确定哪些 NPC 在场
2. 将事件写入每个在场 NPC 的「目睹」或「亲口说」
3. **不写入不在场角色（包括主角）的视角文件**
4. 主角后来可通过以下方式获知：别的 NPC 告诉主角 / 主角发现痕迹 / 第三方转述

### 每回合操作流程

```
┌─────────────────────────────────────────────┐
│ ① 用户选择了一个选项                         │
├─────────────────────────────────────────────┤
│ ② AI 确定「本场景在场的所有角色」            │
├─────────────────────────────────────────────┤
│ ③ AI 读取所有在场角色的视角文件              │
├─────────────────────────────────────────────┤
│ ④ AI 基于各自的视角文件生成对话              │
│    — 林雪只知道林雪视角里的信息               │
│    — 苏云溪只知道苏云溪视角里的信息           │
│    — 每个NPC的话都只反映他们知道的东西        │
├─────────────────────────────────────────────┤
│ ⑤ 更新视角文件：                             │
│    — 所有人目睹的事件 → 写入所有人的「目睹」   │
│    — 某人说了什么 → 写入该人的「亲口说」      │
│    — 某人听到什么 → 写入该人的「听闻」        │
│    — 某人交出了秘密 → 写入接收者的「听闻」    │
├─────────────────────────────────────────────┤
│ ⑥ 更新 session.json（好感度/flags/状态）     │
└─────────────────────────────────────────────┘
```

### 与存档系统的集成

```
保存时：
  save_N.json 读取所有 perspectives/*.md 的内容
  作为 save_N.json 的 perspectives 字段存入

读档时：
  save_N.json 的 perspectives 字段还原为 .md 文件
  写入 perspectives/ 目录

说明：
  这样存档/读档时视角信息不会丢失
  同时保持运行时使用 .md 格式方便 AI 直接读取
```

```markdown
|------|------|----------|----------|
```

### 正确 vs 错误示例

❌ **错误**（记忆泄露——林雪知道了主角没告诉她的事）：
> 林雪：（江晓渔……你听说了吗？主角最近在学吉他呢）
> ※ 但主角只对苏云溪说过自己在学吉他！林雪不应该知道！

✅ **正确**（林雪只知道她亲耳听到的事）：
> 林雪：（主角……刚才江晓渔说你最近在学吉他，是真的吗？）
> ※ 「从江晓渔处得知」——写入林雪的「听闻」，角色动机清晰

❌ **错误**（林雪引用主角的内心秘密）：
> 林雪：「你不用强装笑颜，我知道你爸爸生病的事让你很难过。」
> ※ 主角只对程念慈说过家里的事，林雪怎么可能知道？

> ※ 林雪不知道具体原因，只能表达观察到的状态

## 与 Claude Code 的集成

Claude Code 可以直接读写 JSON 文件，因此：

### 启动命令模板

```bash
# 用户启动/galgame-project 目录下：
ls .galgame/session.json && echo "有存档" || echo "新游戏"

# AI 读取存档
cat .galgame/session.json

# AI 写入存档
echo '{...}' > .galgame/session.json
```

### 通用写入函数（AI 辅助用）

当使用 Claude Code 时，AI 可以通过以下方式操作存档：

```
读取：cat .galgame/session.json
写入：将 JSON 写入 .galgame/session.json 或 .galgame/save_N.json
检查：ls .galgame/*.json 查看有哪些存档
```

## 总结

这个记忆系统确保：

1. **上下文溢出时不会丢失关键信息** — 通过文件持久化
2. **每个选择都有后果** — 好感度/flags 精确追踪
3. **随时可以存档读档** — 多存档位 + 自动存档
4. **中断后可无缝恢复** — session.json 每回合更新
5. **State Card 让 AI 随时知道自己在哪里** — 上下文内永远有一份摘要
6. **自定义输入完整记录** — 用户的自由行动也会被存档记住，恢复时自然回顾
